   `crates/interaction-runtime/src/providers.rs` 仍未讀這個旗標把 evidence level 降級，留給下一輪整合。

   interruptible read，留給下一輪。只影響 fallback 路徑；真硬體走的 `serialport` 有 200 ms 讀取逾時，
   不受影響。

## 3. 功能性殘留缺口

11. **原生資料夾選擇器沒有自動化驗收**：`tauri-plugin-dialog`（僅 `main` 視窗）只通過
    `cargo check`／`clippy`／`cargo test` 的編譯驗證；vitest 的 IPC 是 mock，Playwright 跑的是瀏覽器版
    （沒有 Tauri IPC）。實際能否開出對話框需要桌面手動驗收。
12. **HTTP 逾時分類保守**：declarative HTTP 動器的送出結果分類依賴 `reqwest::Error::is_connect()`／
    `is_builder()`；任何其他錯誤（例如連線後的 TLS 握手失敗）都保守歸類成 `OutcomeUnknown`（回報
    uncertain）。方向安全（不會謊稱「已送出」），但可能把少數真的沒送出的請求也標成不確定而非可重試的
    `failed`。
13. **`stdio JSON Lines` transport 只有規格**：`docs/character-protocol/README.md` §8.1 已改為誠實描述
    （不再宣稱有 `CharacterTransport` trait），但 host 端仍不 spawn 子程序，也沒有 stdio fixture——只有
    WebSocket 是真的外部 transport。
14. **`characterLiveState` 尚未併入 `statusProjection.ts`**：角色生命週期人話目前只在
    `CompanionPage.characterLiveState`，不是集中投影模組的一部分（Phase 8 開放問題 (7)，本輪未處理）。
15. **Tauri 覆蓋視窗（安全狀態）無 Playwright 覆蓋**：只有 Rust 單元測試＋瀏覽器 DOM（`?window=overlay`）
    驗證，沒有真視窗自動化。
16. **匯入角色路徑只有單元／模擬器證據**：尚未在真 Tauri 視窗以真實匯入資料夾走過完整流程。
17. **外部角色 adapter 不再能合成人類互動觀察**（`character-protocol-043`／`safety-invariants-077` 修復
    的直接後果）：外部（WebSocket）adapter 現在完全沒有管道讓一次使用者互動落成 Runtime 觀察（只留稽核
    row，`character.input-not-observed`），比原本「有繞過安全閘門的漏洞」更嚴格，但也代表未來若要讓外部
    adapter 真的回報使用者互動，需要新的專屬 receptor 命名空間（例如 `character.external.click`）與同意
    設計，本輪未做，只是把不安全的舊行為關掉。
18. **agent session resume 的原始 workdir 未持久化**（`agent-honesty-022` 殘留）：`resolve_gateway_workdir`
    已擋掉任何指到或包含 runtime state 目錄的 workdir，桌面端也會把原始 session 的 workspace scope 帶進
    續租請求，但 resolved workdir 本身從未寫進 `AgentSessionRecord`（改 `interaction-core/src/agent.rs`
    超出本輪 AREA）。一個對外宣告「無工作區範圍」但改送別的 workdir 的續租請求，目前仍會被接受。CLI
    `interact-ai agent open --resume <id>` 省略 `--ttl`／`--max-cost` 時現在會被誠實拒絕（不得放寬時間／
