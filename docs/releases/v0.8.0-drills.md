# v0.8.0 可重現擴充演練

從乾淨已提交checkout，先安裝Rust與桌面pnpm lockfile依賴、Swift（macOS），執行：

```sh
CARGO_INCREMENTAL=0 CARGO_BUILD_JOBS=4 bash scripts/tests/architecture-checks.sh --drills --evidence-dir /tmp/aip-drills-new-run
```

四個runner實際涵蓋五個任務。optional-state預設`git archive HEAD`建立暫存樹；不需未推送分支、
使用者home或聊天內容。必要依賴缺少就FAIL，不把靜態lint當實跑。結果與量測尚待本輪clean checkpoint寫入。

| 演練 | 修改模組與原因／production路徑 | 人工決策與背景知識 | 故障恢復與資料保護 |
|---|---|---|---|
| 新增角色 | `examples/characters/drill-text/manifest.json`重用text adapter；`character-package.mjs`經native host package install/list/load與TS renderer factory | 先判斷既有adapter是否滿足呈現，滿足就只加package；新renderer才動組合根；需了解CPP manifest與adapter meta | 不改Core、不加角色字串特判；缺asset或不支持entrypoint拒絕；只在自身暫存目錄操作 |
| 受限裝置 | `state-applied-serial.template.json`→production DeviceLink/DeviceBinding/StateAppliedTracker→pty；`restricted-device.py`跑五組bound/能力/回執/lifecycle回歸 | 先區分event-source、intent-only、full-state與當下確認；639-byte UTF-8含frame，不把ACK當applied | 斷線/新世代/撤銷清outstanding；無applied舊peer保持unconfirmed；不是ESP32真板 |
| optional state | `optional-state.mjs`於archive套已提交patch，變更state→schema→codegen→consumer宣告與共享fixture；三端與frozen corpus守門 | 新欄位是否有產品用途、各consumer應處理或刻意忽略須人為定義；工具只機械傳播，不代替語意決策 | 刻意缺schema/consumer/fixture、null/數值字面/凍結樣本突變均需以指定原因失敗；修復後綠；演練欄位不留production |
| disable→enable | `provider-disable-reenable.sh`→production CLI→daemon lifecycle＋pty，手動關閉受器後兩次啟停，再整個daemon restart | 保留使用者意圖與重新計算有效值不同；高風險預設off，不能還原consent | 每步讀provider/audit/generation，未Ready不Available；只關自身provider/程序；Removed仍experimental |
| 移除package保留資料 | `character-package.mjs`同一真host use case install→choose→remove；TS fallback/原pref與restart重新load | 移除的是package資產，使用者偏好/audit/Session不是package；需理解host store owner | 有效fallback、原使用者資料與稽核保留；結果是native host port＋TS整合測試，不冒稱點過原生移除UI |

每次runner保存精確command、exit、elapsed與source SHA；人工背景/決策是工程判斷紀錄，
不冒充非開發者測得的理解時間。沒有同環境舊版五演練baseline，因此不報架構改善百分比。
既有RendererPort/DevicePort無productionconsumer的限制見[ledger](../aip/deprecation-ledger.md)。
