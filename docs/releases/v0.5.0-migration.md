# v0.5.0 遷移指南（API／CLI／Schema／使用者可見變更）

> 這裡只列**使用者或整合者會看到差異**的變更。不影響外部行為的內部重構不列。所有變更皆為新增或行為
> 誠實化（不刪除既有欄位、不縮小回應形狀），除非特別標註「BREAKING」。

## HTTP API

### 新端點

| 端點 | 權限 | 用途 |
|---|---|---|
| `POST /v1/onboarding/preview` | human token only | 首次設定精靈的零副作用試算：body 與 `/v1/onboarding/commit` 相同，回應是 `{receptors,actuators,starterRecipes,policyPatch,preferences,changed}` 形狀的 diff，不寫入任何狀態。 |
| `POST /v1/mobile/devices/{id}/sensors/stop` | human token only（agent/session 403） | 只停指定 iPhone 的感測，回 `{deviceId,requested,connected,outcome,waitedMs,via}`。 |
| `POST /v1/mobile/devices/{id}/test` | human token only（agent/session 403） | 對指定 iPhone 送 WebSocket ping，回 `{deviceId,ok,connected,latencyMs?,uncertain?,reason?}`；`ok:true` 只代表連線有回應，不代表 App 功能正常。 |

### 回應形狀變更（新增欄位，非 BREAKING）

- **`POST /v1/sensors/stop`**：回應從固定的 `{"stopped": true}` 改為
  `{"stopped": bool, "uncertain": bool, "local": {"microphone": "stopped"|"idle"}, "devices": [{"deviceId",
  "name", "outcome": "stopped"|"unknown"|"unreachable", "waitedMs", "via": "ack"|"status"}]}`。
  **舊的呼叫端若假設回應永遠是 `{"stopped": true}` 需要更新**——`stopped` 現在可能是 `false`，
  `uncertain` 可能是 `true`，代表至少一個來源（通常是連線中的 iPhone）沒有在 ~2 秒內確認。
- **`POST /v1/emergency-stop`** 的回應／事件／audit payload 新增兩個欄位：
  - `"sensors"`：與上面 `/v1/sensors/stop` 相同形狀的報告。
  - `"characterEmergency"`：`[{"deviceId", "outcome": "acknowledged"|"refused"|"unknown"|"unreachable"}]`
    ——每台已連線 iPhone 的緊急狀態投影結果。沒有手機連線時是空陣列（不是省略欄位）。
- **`activity_inbox`（收件匣／待決定 API）** 新增 `"pendingCountExact": bool`。`false` 代表 `pendingCount`
  是下限（尚有未掃描到的待決定項，超過 1000 筆開放收據或 1000 筆知識候選時觸發），不是總數；讀取端
  看到 `false` 時不應顯示「目前沒有待決定事項」這類絕對語句。
- **`GET /v1/providers`／`GET /v1/providers/{id}`**：非人類 principal（agent token、agent-session token、
  character adapter token）呼叫時，回應裡的 `identity.fingerprint` 一律省略（`null`）。人類 token 不受影響，
  仍能看到已配對 iPhone 的公開身分指紋。這是安全邊界修復，不是功能移除——之前 agent token 打
  `/v1/mobile/*` 會被拒，但可以繞道 `/v1/providers` 讀到同一份指紋，現在補上了。
- **`POST /v1/character/hello`**：新增可選欄位 `reducedMotion: bool`（缺省視為 `false`）。桌面視窗的
  hello 現在會帶上視窗的 `prefers-reduced-motion` 值；外部 WebSocket adapter 若不送這個欄位，行為與
  之前相同（協商出 `reducedMotion: false`）。
- **`GET /v1/character/instances`／`GET /v1/character/adapters`**：這兩個端點在 v0.5 Phase 8 就已經回報
  `author`／`version`／`inputCapabilities`（adapters 另有 `characterDisplayName`／`adapterKind`／
  `executable`／`network`），本輪只是訂正了文件裡「API 缺這些欄位」的錯誤描述，API 本身沒有變化。

## CLI

- `interact-ai mobile stop-sensors <device-id>`、`interact-ai mobile test <device-id>`：對應上面兩個新的
  每機端點，直接印 JSON。
- `interact-ai events` **仍然只有 `--seconds`，沒有 `--limit`**（`docs/character-protocol/reference-adapters.md`
  舊範例誤寫成 `--limit`，本輪已修正文件；CLI 行為本身沒有變化，用 `interact-ai events --seconds 5 --json`）。

## 宣告式硬體 YAML（`interaction-adapter-declarative`）

- `CapabilitySpec` 新增可選欄位 `limits:`（`maxMagnitude`／`maxDurationMs`／`maxPerHour`／
  `maxPatternSteps`／`maxPayloadBytes`，camelCase）——宣告裝置安全上限，讓 Policy Governor 的
  `min(AI 請求, 使用者偏好, session 限制, 裝置安全上限, 剩餘預算)` 鏈終於拿得到「裝置安全上限」這一項。
  不宣告就是 `None`（沒有裝置端上限，行為與之前相同）。荒謬的上限（`maxMagnitude` 超出 `0..=1`、或
  duration／per-hour／pattern-steps 為 `0`）在 parse 時會被拒絕（避免靜默擋死所有動作）。
- `MqttSpec` 新增可選欄位 `livenessTimeoutMs`（預設 `15000`，即 15 秒，夾在 200 ms 到 1 小時之間）——
  超過這個時間沒收到裝置在 device topic 上的訊息，健康度會從 healthy 降級為 degraded（仍可用，只是
  誠實標示「連線還在，但已 N 秒沒聽到裝置」）。
- `pairingCode`／MQTT password 若以明文寫在 YAML 裡（不是 `secret://` 參照），`build()` 現在會
  `tracing::warn!` 並記錄在 `BuiltCapabilities.warnings`（不阻擋既有 spec，建議儘快改用
  `secret://<name>`）。

## 環境變數

- 新增 `INTERACT_AI_MOBILE_ADVERTISE`：設為 `0`／`false`／`off`／`no` 時關閉 iPhone 配對伺服器的 Bonjour
  區網廣播並只綁 `127.0.0.1`（原本一律綁 `0.0.0.0` 對區網廣播）。主要給 CI／E2E 用，避免測試期間對實體
  區網廣播；一般使用者不需要設定它（預設行為不變）。

## iOS App（wire protocol）

- `ServerMessage.stopAll` 新增可選欄位 `"reason": "user"|"emergency"`；缺席或無法辨識的值一律 fail-safe
  解讀為 `.emergency`（不會因為新欄位缺席就誤判成比較寬鬆的狀態）。
- `ClientMessage.ackStopAll` 的 ack 訊息新增回聲欄位 `"sensors": bool`：`{"type":"ack","stopAll":true,
  "sensors":<echo>}`。桌面端目前用 `serde_json::Value` 讀 ack（只看 `stopAll==true`），新欄位不影響
  既有解析；桌面端已於第二輪修復（`docs-claims-068`）補上送出 `reason`（`user`／`emergency` 依觸發路徑區分），
  但**尚未消費新的 `sensors` 回聲**（見已知限制）。

## 前端（僅供其他整合此 API 的專案參考；不是公開契約，但行為值得記錄）

- `src/character/registry.ts` 的 `capabilitySummary()` 回傳行的**順序**改變（一般模式的行移到技術行前面），
  文字內容不變；新函式 `capabilitySummaryParts()` 回傳分層後的 `{general, technical}`。
- `CharacterCard`（`src/pages/character/catalog.ts`）新增必要欄位 `technical: string[]`——任何自行建構
  `CharacterCard` 字面值的程式碼都要補上這個欄位。

## 資料庫／Storage

- 無 schema 版本變更（storage v8 沿用）；所有新欄位皆為既有表格上的可選 JSON 欄位，舊資料可正常讀取。

## 不影響使用者、但影響「已測試」證據歸屬的行為

- 多台 iPhone 同時連線時，動作（haptic／notify／tts／torch／flash／character.present）現在**必須**指定
  `extra.deviceId`；只有恰好一台連線中才能省略。這是誠實化而非功能移除——之前的行為是靜默送給
  BTreeMap 排序後的第一台，使用者以為指定了某台手機，實際上可能是另一台在動。
