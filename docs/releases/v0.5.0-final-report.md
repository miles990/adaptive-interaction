## 18. 安全不變量檢查

- Policy Governor `min()` 鏈本輪只新增「裝置安全上限」輸入，未移除既有比較項。
- AI 仍不能授予 consent、不能解除 emergency stop、不能提高後端安全上限；`RUNTIME_ONLY_STATES` 反而
  收緊了 AI 可投影的真相狀態（emergency／verified-success 收回 Runtime 專屬）。
- 感測器仍預設關閉；emergency stop 仍不因重啟自動恢復（本輪未改動這條路徑）。
- 模擬／dry-run 未產生任何外部副作用（`preview_onboarding`／`device-acceptance.sh --dry-run` 皆為
  零副作用試算或印出請求不送出）。
- 誠實階梯（queued≠completed；acknowledged≠completed；completed≠verified；inference≠fact）在本輪
  全部修復中維持，且多項修復本身就是在補這條階梯的漏洞。
- 未發現任何本輪改動使既有不變量鬆動的案例。

12 位 agent 的 stage-1 報告中，絕大多數修復都附帶「暫時把 bug 放回去 → 對應測試轉紅 → 還原 → 復綠」的
實測記錄（而非僅靠邏輯推論紅燈存在），部分修復（如 mobile-server 的 DoS 上限、若干結構性斷言）以
「移除該行即無法通過」的方式設計斷言、未逐一實際回插驗證，各 report 均誠實標註兩者的差異。精確統計
（多少項實測回插 vs. 多少項僅結構性保證）：未逐一計數（12＋7 份報告的 `testCommandsRun`／`regressionTest` 欄位保留原文於
`docs/reviews/adversarial/` 對應 run 與本次 session 的 stage 報告），本文件不臆測比例。

## 27. 併發衝突觀察與已排除項目

整合者留意的合併風險是 §22 提到的共用檔案並行編輯。
