## 這一輪（Phase 9）對真機驗收準備工作做了什麼

`apps/interaction-ios/` 新增了可重跑的裝置建置與驗收腳本，本身已在本機跑過「誠實拒絕」路徑（見下），
但尚未在真機上跑完整流程：

- **`apps/interaction-ios/scripts/device-build.sh`**：五道前置關卡（完整 Xcode／恰好一台已連接的 iOS
  裝置／`developerModeStatus == enabled`／簽章 Team ID／`xcodebuild` 建置），任何一關沒過就印出明確的
  人工步驟並以非零碼結束，**不會**呼叫 `xcodebuild`。過關後才 `xcodebuild -allowProvisioningUpdates
  -allowProvisioningDeviceRegistration build`，再用 `devicectl install app` 與 `devicectl process launch`
  裝到手機上並啟動。
  - 本機實測（`--check-only`，Developer Mode 尚未開啟時）：停在「iPhone 的 Developer Mode 目前是 disabled」那一關，`exit 1`，
    `xcodebuild` 從未被呼叫；使用者開啟 Developer Mode 並在 Xcode 登入 Apple ID、於專案選定 Personal Team 後，五道閘門全過。
- **`apps/interaction-ios/scripts/device-acceptance.sh`**：18 列驗收矩陣（配對、狀態、haptic、通知、
  TTS、手電筒開／關、閃光、角色六態、角色驗證被拒、觀察 motion/battery/touch/mic、BLE 掃描、停止感測、
  緊急停止、解除緊急停止、撤銷），每一列走真實 HTTP（`POST /v1/plans` → `execute` → `GET /v1/actions/{id}`）
  並印出 Requested／Effective／Dispatched／Acknowledged／deviceApplied／outcome——**不做任何 pass/fail
  判定**，只忠實印出 daemon 回傳的內容；缺答案一律印「未知(uncertain)」。破壞性列（緊急停止等）需要
  `--confirm-destructive`；任何會改變同意狀態的操作除非帶 `--grant-consent`，否則只印出人類需要另外執行
  的命令，絕不靜默授予同意。
  - 本機實測：`--list-rows` 列出 18 列；`--dry-run --confirm-destructive` 印出每一列的完整 HTTP 請求但
    不實際送出；沒有 daemon 可連時誠實印出「先啟動 `interact-ai serve`」的指示區塊而不是原始 curl 錯誤。
    **兩者皆未對真手機或真 daemon 跑過**。

## 需要的人工步驟（依序）

1. 在 iPhone 11 上：設定 → 隱私權與安全性 → 開發者模式 → 開啟 → 重新開機 → 確認。
2. 在本機 Xcode：登入一個 Apple ID（Xcode → Settings → Accounts → 「+」）。免費 Personal Team 即可，
   但要注意下方「免費帳號限制」。
3. 用 USB 把 iPhone 接上本機、在手機上點「信任這台電腦」。
4. 執行 `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer
   apps/interaction-ios/scripts/device-build.sh`（帶 `IOS_DEVELOPMENT_TEAM=<你的 Team ID>` 若自動偵測不到）。
5. App 裝上手機後，啟動桌面 `interact-ai serve`，在手機上完成 QR／手動配對。
6. 執行 `apps/interaction-ios/scripts/device-acceptance.sh --grant-consent`（視需要的列再加
   `--confirm-destructive`），把逐列輸出存下來作為證據。
7. 把證據（腳本輸出、螢幕截圖）與本文件的「將會記錄什麼」一節逐項核對，回填到
   `docs/acceptance-evidence.md` 與本文件，並移除「NOT YET VERIFIED」標題。

## 禁止資料政策（Forbidden-data policy）

- **絕不**把裝置 UDID、Team ID、簽章憑證內容、配對 token、pairing code 或任何機密寫進本文件、commit
  訊息或截圖檔名。腳本本身已遵守同一規則（`device-build.sh`／`device-acceptance.sh` 的 `--json-output`
  一律寫到 `mktemp` 目錄，程序結束即刪除；echo 出的配對碼一律遮蔽）。
- 螢幕截圖若不小心帶到手機序號、電話號碼、通訊錄或其他個資，一律裁切或打碼後才能提交；不確定就不提交。
- 真機測試僅使用測試用／非個人的 iPhone；不得用連結真實個人資料（聯絡人、相簿、健康資料）的裝置做
  驗收，或必須先確認該裝置的資料不會被本專案的 receptor（如 `iphone.mic-level`）意外取用並外洩到證據裡。
- 本文件與其引用的截圖只記錄「系統行為是否符合規格」，不記錄裝置持有人的個人資訊。
