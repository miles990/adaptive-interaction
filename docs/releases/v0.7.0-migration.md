## 2. 新的裝置線訊息：`aip-frag`（裝置線 v1.2）

`proto` 仍為 **1**；`aip-frag` 是**追加**訊息型別，舊韌體忽略、舊 host 丟棄。

- **只在對端宣告能力時使用**：裝置必須在 `hello` 的 `caps` 裡包含 `aip.frag/1`；沒有宣告的裝置
  完全走 v1.1 路徑（超過單行上限就照舊拒絕，`reason: over-line-limit-no-fragmentation`）。
- **入站對稱**：沒有宣告 `aip.frag/1` 的裝置送來 `aip-frag` 一律拒絕（`reason: not-advertised`）＋稽核。
- **frame 欄位**：`xferId`／`seq`／`total`／`bytes`／`crc32`。
- **有界**：每裝置 1 筆 in-flight（新的 xfer 取消前一筆並稽核）、重組上限 8 KiB、片數上限 64、
  自最後一片起 2 s 逾時；`hello`／斷線／revoke／stop-all／rebind 一律取消。
- **失敗一律整筆丟棄**：seq 重複／亂序／缺片／截斷／header 不符／crc 不符／bad JSON／惡意 `total`
  在第一片就拒——並留 `aip.fragment-dropped{xfer,reason,received,total}` 稽核。
- 參考韌體**刻意不宣告** `aip.frag/1`（真板上分片路徑零執行）。

實作位置：`crates/interaction-adapter-declarative/src/fragment.rs`＋`DeviceLink`／`AipChannel`；
核心（`interaction-session`／`interaction-aip`／`character_session.rs`）零變更。
契約：`docs/aip/transport-bindings.md` §8、`docs/aip/device-profile.md` §6.3、
相容承諾登記於 `docs/aip/deprecation-ledger.md` §3.2。

**單行上限（實測）**：serial 639、MQTT 639、**BLE 480**（v0.6.0 文件寫 512，本輪更正為實測值）。

## 3. 新的 `payload.reason` 值：`recovery`

AIP 1.0 的**澄清**，wire 形狀與 `specVersion` 不變。

- host 只在「同一個 session、`epoch` 不變、權威狀態真的比該成員記得的舊」時，對**該成員**的 resume
  回一則 `state{kind:"snapshot", payload.reason:"recovery"}`（`REASON_RECOVERY`；計數
  `counters.snapshots.recovery`）。
- 接收端規則 6：只有 host 明說 `recovery` 且 epoch 相同，才允許 revision 退回並採納。
- **舊接收端相容**：只認得舊 reason 值的實作把它當成「沒有 reason 的 snapshot」＝ v0.6.0 行為
  （被 rollback 防護忽略）。這正是 v0.6.0 卡住的那條路徑，不會比原本更糟。
- 被移除的是 Runtime 那段「把這種 snapshot 改寫成 `session-reset`」的補救——它其實無效
  （同 epoch 的 `session-reset` 一樣被忽略），已先以測試重現無效性再刪。

契約：`docs/aip/character-session.md` §6／§7.2；`docs/aip/README.md` §6。

## 4. 新的路由、指令與欄位（全部向後相容）

### 4.1 HTTP（人類層 token；agent token 一律拒絕）

| 路由 | 用途 |
|---|---|
| `GET /v1/sensors/unresolved` | 「沒有人確認過結果」的感測停止摘要（有界 32） |
| `POST /v1/sensors/unresolved/{sourceId}/dismiss` | 人為解除（body `{"generation": N}`，`generation` 必填）；回應與稽核都寫死 `confirmedStopped:false` |

`GET /v1/sensors/unresolved` 已加進 agent token 的 GET 排除清單（`/v1/sensors/stop` 仍放行）。

### 4.2 CLI

```bash
interact-ai sensors unresolved
interact-ai sensors dismiss <sourceId> --generation N
```

### 4.3 新增的唯讀欄位（都是選填／非空才序列化，舊呼叫端不受影響）

| 位置 | 欄位 | 值 |
|---|---|---|
| `GET /v1/status` | `unresolvedStops[]` | `sourceId`／`generation`／`sensors`／`since`／`lastKnown`／選填 `sourceLabel`（人話名稱；查不到就省略，`sourceId` 不冒充人話名稱） |
| `GET /v1/status` | `characterSessionSync[]` | 每個成員的 `syncProfile` |
| `GET /v1/character-session/diagnostics` | `members[].syncProfile` | `full-state`／`intent-only`／`event-source`；查不到出站通道就省略 |
| 稽核 | `aip.member-sync-profile` | `deviceId`／`transport`／`role`／`syncProfile`／`maxLineBytes`／`supportsFragmentation` |
| 稽核 | `aip.fragment-dropped` | `xfer`／`reason`／`received`／`total` |
| 稽核 | `provider.rebinding`／`provider.rebound`／`provider.rebind-failed{reason}`／`provider.rebind-superseded`／`provider.rebind-not-started`／`provider.rebind-not-tracked` | rebind 生命週期 |
| 稽核 | `provider.rebound.keptDisabledReceptors` | rebind 時保留為關閉的非 consent 受器 |
| 稽核 | `aip.outbound-undeliverable.envelopeBytes` | 送不出去那一則的整行 bytes（`reason` 受 64 字元上限截斷，長度改由這個欄位表達） |
| 稽核 | `sensor.unresolved-stop-dropped` | 未解決停止摘要滿 32 筆時丟最舊 |
| 稽核 | `aip.rejected{stage:"provider-binding"}` | 綁定不是 `Bound` 時擋下的入站 `aip` |

`status.unresolvedStops` 與 `GET /v1/sensors/unresolved` 序列化**同一筆記錄**，欄位逐欄相同，由 API 測試釘住。

### 4.4 生成常數（TS／Swift 由 codegen 讀同一個數字）

| 常數 | 值 | 意義 |

| `MAX_REALIGN_ATTEMPTS` / `maxRealignAttempts` | **3** | 連續 3 次未能套用＝unrecoverable |

## 5. 行為變更清單與對呼叫端的影響

| # | 變更 | 誰會看到 | 要做什麼 |
|---|---|---|---|
| 5.1 | **`transition_provider(id, Available)` 對宣告式裝置回傳 `Disconnected`**（不是 `Available`）：重新啟用只代表「允許再試一次」，握手成功才收斂 | 任何呼叫 `PATCH /v1/providers/{id}` 或 Rust `transition_provider` 並假設「回傳狀態＝請求狀態」的程式 | 改成等待狀態收斂（rebind 一般在數百毫秒到 40 s 內結束）或讀 `provider.rebound` 稽核。桌面已改：條目顯示「重新連線中」／「沒有重新連上」＋人話原因 |
| 5.2 | **`MAX_RESUME_PATCHES` 1024 → 512**，且超過上限從「截斷後 realign」改為**整批不處理**＋`realign(resume-too-long)` | 桌面與 iPhone 的 resume 路徑 | 無須動作（host 超限時本來就會改回 snapshot）。自製客戶端若沿用 1024，改讀 `AIP_LIMITS.maxResumePatches` |
| 5.3 | **realign 有界預算：第 4 次 → 第 3 次未能套用即 unrecoverable** | 三端接收機的「無法恢復」文案觸發時機提早一次 | 無須動作；自製客戶端改讀 `maxRealignAttempts` |
| 5.4 | **`epoch` 不同但沒有 `session-reset` 宣告 → realign**（以前 Rust／Swift 直接套用並靜默改寫本地 epoch）；patch 也開始檢查 epoch | 所有接收端 | 無須動作；host 的 resume 對 epoch 不同會回 `session-reset`，一次收斂 |
| 5.5 | **缺 `hash` 或缺 `state` 的 snapshot 一律 `reject-invalid`**（以前 TS／Swift 不核對就套用） | 自製 host／測試替身若送不帶 hash 的 snapshot | 補上 `payload.hash`（`state` snapshot 一律必帶） |
| 5.6 | **取消 `allowRegression`／`hostRegressed`**：同 incarnation 的回退不因「HTTP 回覆最新」而合法 | 桌面接收機 | 合法的回退改用 `reason:"recovery"`（§3） |
| 5.7 | **停用／撤銷的順序改為「先請來源停止 → 再關連線 → 最後翻旗標」** | 觀察稽核順序的測試／工具 | 稽核序列改變（`sensorStop` 出現在 `closedLinks` 之前）；停止結果不再必然是 `unknown` |
| 5.8 | **rebind 保留人類手動關掉的非 consent 受器**（`provider.rebound.keptDisabledReceptors`） | 依賴「重新啟用＝回到預設能力」的流程 | 無須動作；要真的回到預設請重新啟動 daemon |
| 5.9 | **`GET /v1/sensors/unresolved` 是人類層**：agent token 403 | agent 整合 | 用人類層 token；`/v1/sensors/stop` 不受影響 |
| 5.10 | **桌面進階診斷的 alignment 計數改名**（`stale`→`staleConnection`、`invalid`→`rejectedInvalid`、`ignoredRollback`→`ignoredStale`；移除 `hostRegressed`；新增 `recovered`／`rejectedIdentity`） | 讀那些標籤的截圖／文件 | 更新截圖與引用 |
| 5.11 | **同步卡新增 `partial-sync` 態**（info，不是綠勾）：非 `full-state` 的成員不再顯示「已同步」 | 桌面 UI 的既有截圖與 `docs/DESKTOP-GUIDE.md` 的狀態表 | `DESKTOP-GUIDE` 那一列尚未補（見已知限制 §4.7） |
| 5.12 | **BLE 單行上限文件值 512 → 480**（更正為實測值，程式碼本來就是 480） | 讀文件估算 payload 的人 | 依 480 重新估算 |
| 5.13 | 通用停用不再關掉家族共用的能力旗標——**這是既有行為**（本分支較早的 `f250acf`，v0.6.x 段），本輪未改，rebind 沿用同一語意 | — | 無須動作 |

## 6. 沒有變的事（明確聲明）

- AIP `specVersion`、12 種 message type 的形狀、Outcome 誠實階梯、錯誤碼集合：不變。
- 裝置線 `proto`：仍為 **1**（v1.2 是同一個 proto 下的追加訊息）。
- CPP（Character Presentation Protocol）契約：不變（本輪未動 `crates/interaction-character`）。
- `interaction-session`／`interaction-aip` 在 M2 分片那一批的 `git diff --stat` 為空：分片完全在
  transport binding 內部，`character_session.rs` 只多了 `derive_sync_profile` 這個純推導。
- 既有 HTTP 路由、SSE 事件型別、CLI 子指令：沒有移除、沒有改名。

## 7. 回退方式

| 想回退什麼 | 怎麼做 | 代價 |
|---|---|---|
| 整個版本 | 裝回 v0.6.0 的二進位；狀態檔不需轉換（§1） | 半套用的陪伴預設交易不會被補送；`unresolvedStops` 消失（它本來就不跨重啟） |

| 只關掉 Character Session | 既有的 `INTERACT_AI_CHARACTER_SESSION` feature flag（登記在 `docs/aip/deprecation-ledger.md`，真機／真板證據為零之前不得移除） | 桌面同步卡與 AIP 路由整組停用 |
