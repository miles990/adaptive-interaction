### 4.2 Desktop（Runtime 真相）→ iPhone（模擬 fixture／模擬器）：`task.verified` → celebrate

- Runtime `EventType::AgentSessionState{verified}` 轉成 AIP `event{name:"task.verified"}`（§13 相容表，
  `docs/aip/README.md`）→ `interaction-session` 的確定性 Director 產生 `celebrate` Behavior Intent →
  投影成 CPP intent 送到已協商的 adapter；同時 iPhone `aip` frame 收到同一個 intent。
  單元證據：`interaction-session/tests/pure_functions.rs`（Director `task.verified→proud+celebrate`
  案例，屬於 13 個案例之一）；iOS 端純函式證據：`SessionClientTests` 內
  `testTheAppCanNeverBuildAVerifiedResult`（確認手機端**無法自行合成** `verified`，只能呈現 Runtime
  推來的 intent，不得反向宣稱驗證）與 `testTheSameIntentMessageIsNeverPlayedTwice`。
- **`claimed-completed ≠ verified` 在 Session 層同樣成立**：`interaction-session/tests/security_matrix.rs`
  與 `docs/aip/README.md` §3 的不變量（`verified` 只能由 Runtime 送，adapter／device／renderer 送來的
  一律 `rejected{scope-denied}`）；本輪未新增額外的端到端截圖（沒有 UI 場景可以直接誘發
  celebrate 並截圖，屬於 §6 的已知缺口之一）。

### 8.2 CLI E2E 第一次失敗的定位

第一次全套跑出的唯一失敗：

```
FAIL: 斷線誠實反映成 presence offline (got 'False', want 'True')
```

**根因是驗收腳本本身的斷言過舊**：`reconnect-recovery-044`（本輪對抗審查 confirmed finding，已修）把
斷線後的行為從「立刻 offline」改成「先進 `Presence::Reconnecting`，逾時後才由 session tick 轉
`Offline`」（`crates/interaction-runtime/src/mobile.rs` 斷線收尾；回歸測試
`crates/interaction-session/tests/session_hardening.rs::reconnecting_is_a_transport_fact_the_session_projects_faithfully`
與 `crates/interaction-runtime/tests/character_session_loop.rs::a_disconnected_member_is_reconnecting_before_it_is_offline`）。
腳本斷言寫在這項修復落地之前，沒有同步更新。修正腳本斷言（改斷言「斷線誠實反映成 presence
reconnecting（成員保留，逾時才 offline）」）後重跑：**96 passed / 0 failed**（`cli-e2e-rerun.log`）。
**這不是產品回歸**，是驗收腳本追不上一則已知且刻意的行為變更。

### 8.3 Playwright 第一次失敗的定位

第一次全套跑出：

```
1) [main] › e2e/character-session.spec.ts:263:1 › 角色同步（模擬 iPhone（fixture））：
   配對 → 已同步 → 摸一下 → 離線 → 重連 → 撤銷（桌面寬度）
Error: 角色同步狀態等不到預期值 …
  5 did not run
  65 passed (2.2m)
```

單一逾時（`waitCharacterSession` 等到 deadline）的根因與 CLI E2E 那則相同：`character-session.spec.ts`
第 5 步在模擬 iPhone（fixture）斷線後等的是 `presence === "offline"` 與文案「iPhone 暫時離線」，但
`reconnect-recovery-044` 修復後的正確行為是 Transport 先送 `Presence::Reconnecting`（成員保留），session
逾時（45 s）後才轉 `Offline`——journey 在 20 s 內等不到 offline 就逾時。修正方式是改測試期待，不是改產品：
spec 改等 `reconnecting` 與「iPhone 正在重新連線」，截圖改名 `*-character-sync-reconnecting.png`（舊的
`*-offline.png` 移除），`docs/releases/v0.6.0-test-matrix.md` 與 `docs/acceptance-evidence.md` 的引用同步。
針對受影響的 3 個 spec（`character-session.spec.ts`／`narrow.spec.ts`／`a11y.spec.ts`，共 30 個測試）
重跑：**30 passed / 0 failed**（`pw-rerun.log`，46.0 s）；之後再重跑一次**完整**套件（不加 `--grep`）：
**71 passed / 0 failed**（`pw-final.log`，2.3 分鐘），確認整套在乾淨狀態下全綠。**這不是產品回歸**，
是驗收斷言追上契約變更；「5 did not run」是 Playwright 在同一 worker 內於失敗後略過該檔其餘案例，
不是被系統中止（那件事發生在 hardening 階段的第一輪，見 §2 備註）。
