# v0.8.0 發布後：rebind 完成稽核的測試競態

[PR #6](https://github.com/miles990/adaptive-interaction/pull/6) 的文件回填在四項 PR CI 成功後 rebase 合併至 `b55c1beb33175ef498ffa395a085f72a5b11bc0b`。該 main 的 [CI 34020702196](https://github.com/miles990/adaptive-interaction/actions/runs/34020702196) 首次執行為 Rust 1263 passed／1 failed／0 ignored（98 binaries），其餘 Tauri、Frontend、Browser 三項成功；沒有把此 run 記為成功。

唯一失敗是 `reenable_rebinds_without_restart`：原測試等到 Bound＋Available，就立即斷言 `provider.rebound` 稽核恰好一筆，實際為空。獨立 Find 確認可達的時序：`DeviceBinding::note_ready` → `converge_provider_after_link_ready` 可先公布可用，背景 `run_declarative_rebind` 稍後才在完成步驟寫入稽核。Available 與背景操作稽核不是同一原子發布；CI 當次排程沒有逐事件 trace，因此精確排程仍是由來源與受控重現支持的推論。

修正 commit `857f009acf0b2c217f12ec041766ad7de2a2c7cf` **只改測試**：同一個既有 25 秒／100ms 輪詢再等完成稽核存在，然後保留恰好一筆、handshake=ready、重新加入 session、高風險預設關閉及 unresolved-stop 的全部原斷言；audit 讀取失敗改為立即明確失敗。沒有延長期限、放寬精確數量或在產品加 sleep。
