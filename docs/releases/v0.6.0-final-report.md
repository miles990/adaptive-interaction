## 7. 架構決策

依 `docs/aip/architecture-boundaries.md`：

**分層（依賴只能朝向核心）**：
```
Presentation/UI/Renderer  →  Application Use Cases  →  Domain Core / Character Session
        →  Ports / Stable Interfaces  →  Adapters / Transport / Platform
```
`interaction-session` 依賴 `interaction-aip`＋`interaction-character`（truth 詞彙）＋serde；不得依賴
tokio／axum／Tauri／SwiftUI／WebSocket／BLE／MQTT／Serial／小樞專屬欄位——由
`tests/e2e/tests/dependency_boundaries.rs` 釘住（`cargo tree` 檢查）。

**Ports**（11 個，`crates/interaction-session/src/ports.rs` 為主）：`CharacterAdapter`／`RendererAdapter`／
`DeviceAdapter`／`TransportAdapter`／`AgentAdapter`／`MemoryProvider`／`SessionStore`／`Clock`／
`IdentityVerifier`／`ConsentVerifier`／`EventLog`。每個 port 只有 3–6 個方法；可選能力一律靠 capability
協商而非 optional method。

**Strangler**（小樞脫離核心，見 §11）：新 crate `interaction-character-shu` 承接原本寫死在
`interaction-character` 核心裡的小樞專屬邏輯；核心新增 `PackMigrator` trait＋有界 `MigrationRegistry`；
`ValidationLimits::default().builtin_whitelist` 改為空，host 注入。第二層 strangler（`25e2a86`）把
「核心以 `iphone.*`／`companion.` 字面前綴判斷跨切面語意」也改成宣告驅動（`ProviderCapabilityRegistry`）。

**Feature flag**：`INTERACT_AI_CHARACTER_SESSION`（env，預設 `1`）。`0` 時 Runtime 不啟動 Session Host，
四條 `/v1/character-session/*` 路由回 `503 session-disabled`，iPhone `aip` frame 回
`error{unsupported-capability}`，桌面同步卡顯示「角色同步目前關閉」，其餘行為回退到 v0.5.1——這是
唯一官方支援的整批回退開關（`docs/aip/architecture-boundaries.md` §5；`docs/releases/v0.6.0-migration.md` §11）。

**提交順序**（架構文件 §6 事先規劃，實際 33 個 commit 大致依此序推進，見 §19）：baseline → docs(aip)

## 8. AIP 1.0 摘要

新 crate `interaction-aip`（純函式、無 tokio／I/O）。契約：`docs/aip/README.md`。

- **Envelope**：versioned（`specVersion: "aip/1.0"`）、12 種 message type（`capability`／`state`／
  `command`／`result`／`event`／`query`／`response`／`error`／`heartbeat`／`cancel`／`approval-request`／
  `approval-result`）各自有必填 profile。
- **Outcome 十二值誠實階梯**：`received≠accepted≠applied≠observed≠claimed-completed≠verified`
  （另含 `expired`／`rejected`／`cancelled`／`cancel-confirmed`／`failed`／`duplicate`），`verified`
  只能由 Runtime 產生。
- **版本協商**：同 major、取較小 minor，不同 major 直接拒絕（`newerMinor` 提示）。
- **能力協商**：確定性交集＋取最小值，不猜測相容性。
- **身分綁定**：宣稱與 transport 層身分不符一律拒絕，不「修正後執行」。
- **19 個穩定錯誤碼**（`schema-invalid`…`session-disabled` 等，見 README §12）。
- **上限**（`interaction_aip::limits`）：訊息 64 KiB、payload 32 KiB、字串 2000 字元、JSON 深度 8、
  去重環 256、事件日誌環 512、時鐘容忍 30 s。
- **離線事件政策表**（`drop-if-offline`／`expire-by-deadline`／`queue-idempotent`／
  `require-reconfirmation`／`state-reconcile`）。
- **證據分類詞彙**（見 §23）。
- **Schema 單一來源**：`schemas/aip-1.0.schema.json` 由 Rust 型別產生（golden），`scripts/aip-codegen.mjs`
  確定性產生 TS／Swift 型別鏡射，`pnpm aip:check` 漂移時 exit 1（本輪四次最終回歸皆 exit 0，見 §21）。
- **三方 conformance**：Rust／TypeScript／Swift 共用同一組 golden fixture，最終數字見 §21／§26。

未知 message type 解析成 `Unknown` 但永不執行；未知選填欄位 round-trip 不遺失；錯誤訊息不回顯輸入。

複製自 `docs/aip/character-session.md` §2（一字不改）：

| 狀態 | Canonical owner | 其他元件能做什麼 |
|---|---|---|
| 角色情緒 `mood{kind,intensity}` | Character Session Host（Director） | 送 event；不得直接改 |
| 角色活動 `activity` | Character Session Host | 同上 |
| 注意目標 `attention` | Character Session Host | 同上 |
| 真相 `truth{state, correlationId}` | Runtime（經 `task.*`／`runtime.*` event 進 Session；Session 只轉錄，不推論） | renderer／device 只能讀 |

| 長期記憶 | Memory Provider（`memory.rs`，MemoryActor 規則） | Session 不碰 |
| Agent 工作狀態 | Agent Runtime（`agents.rs`） | Session 只收 `task.*` |

| iPhone 原始感測資料 | iPhone 本機 | 只送語意事件 |
| 裝置 capability | 對應 Device Adapter（iPhone：MobileBridge；外部 renderer：CPP adapter） | Session 只存協商結果 |
| 畫面位置與縮放 | 各裝置本機 | 不同步 |
| 動畫 frame／particle | 各 Renderer 本機 | 不同步 |

| Session membership／presence | Character Session Host | member 送 heartbeat／join／leave |

程式內約束：`SemanticState` 只有 `CharacterSession::apply` 能改（欄位私有、只回傳 patch）；Renderer／
Device port 沒有任何 setter。

## 10. Character／Renderer／Device／Transport 邊界

依 `docs/aip/architecture-boundaries.md` §2：

| Port | 位置 | 責任 |
|---|---|---|
| `CharacterAdapter` | CPP `CharacterManifest`＋TS `CharacterAdapter`（既有） | 角色 package → renderer 實例 |
| `RendererAdapter` | `interaction-session::ports::RendererPort`（Rust）；TS `CharacterAdapter` | 收 semantic state＋Behavior Intent、本地播放、降級 |
| `DeviceAdapter` | `interaction-session::ports::DevicePort` | 產生 event、接收 state／command、presence |
| `TransportAdapter` | 各 transport 自有（`mobile.rs`、`character_ws.rs`） | framing、重連、退避 |

CPP WebSocket adapter **不**承載 AIP：外部 renderer 仍走既有 CPP wire，Session 的 Behavior Intent 已
投影成 CPP intent（`docs/aip/README.md` §13 相容表）。iPhone wire、HTTP（human token）、SSE、Tauri IPC、
In-process（Rust）五種 transport 綁定見 `docs/aip/README.md` §9；四種 v0.6.0 新增，一種（CPP WS）不變。
Adapter lifecycle 外層穩定語意：`Registered → Initializing → Starting → Ready ⇄ Degraded → Stopping
→ Disposed`（另 `Cancelled`／`Failed`／`Unavailable`／`Removed`），四個內建 adapter（shu／sprite／
text／shape）跑同一套 `adapter-contract.test.ts`。

## 16. 配對與 Endpoint Migration 安全證據

依 `docs/aip/pairing-security.md`：

- **配對碼＋HMAC challenge**：單一、單次使用、記憶體內 `PairingSession`；TTL 300 秒；任何錯誤
  `pair-response` 燒毀整段配對期。測試：`mobile_loop.rs::wrong_pairing_code_is_refused_and_session_burned`、
  `::a_peer_that_burns_the_pairing_window_is_visible_to_the_user`。
- **TLS 指紋固定（TOFU）**：iOS `PinnedWebSocketDelegate`，不符即 `.tlsMismatch`，永不誤判成位址變更。
  測試：`ReconnectHintTests.swift::testTlsMismatchIsNeverReportedAsAddressChange`（模擬器）。
- **每機 Token**：只存 `sha256(token)`，明文只在配對回覆傳一次；重連比對 hash；失敗一律回同一句籠統
  文案，稽核內部記差異但不外洩。測試：`mobile_loop.rs::token_reconnect_works_until_revoked`、
  `::the_public_device_fingerprint_is_not_the_token_verifier`。
- **Revoke 即斷線**：落地失敗即回滾（不留假撤銷）；2 秒內送 `auth-fail{reason:"revoked"}`；同批收斂
  停用高風險受器、退出 Character Session（非 offline，是 leave）。測試：
  `mobile_loop.rs::a_revoke_that_cannot_be_persisted_fails_honestly`、
  `::revoke_disconnects_live_connection_immediately`。
- **`superseded`（活連線被新連線取代）**：`docs/aip/pairing-security.md` §6 原文記載「無測試」——
  **本輪已補上**：`crates/interaction-runtime/tests/character_loop.rs::attaching_while_a_connection_is_live_supersedes_it_with_a_goodbye`
  與 `mobile_loop.rs::a_superseded_connection_still_forces_the_high_risk_receptor_off`
  （`reconnect-recovery-047`／`pairing-migration-003`，已修，見 §27）。`pairing-security.md` 文件本身
  未在本輪更新，讀者若只讀該文件會誤以為仍是缺口，本報告在此更正。
- **Endpoint migration**：同身分（TLS 指紋不變）token 有效性與伺服器目前綁哪個 IP／port 無關；但
  「使用者手動重新輸入配對 QR」實際上會觸發一次全新配對（新 token），不是「只換位址、沿用舊 token」
  的專用流程——`pairing-security.md` §7 誠實指出這是契約意圖與現況的落差，本輪未修。

  7157 幀／29 次抓玩具，GC 前峰值 5.93 MB。**此次量測與其他對抗審查 agent 並行、非獨占機器**
