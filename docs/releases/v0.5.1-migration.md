# v0.5.1 遷移指南（API／CLI／IPC／iOS／使用者可見變更）

> 只列**使用者或整合者會看到差異**的變更。不影響外部行為的內部重構不列。除非明寫 **BREAKING**，
> 所有變更都是新增欄位或行為誠實化（不刪除既有欄位、不縮小回應形狀）。
> 基準 v0.5.0（tag `v0.5.0` ＝ `8b713c7`）。

## 1. HTTP API

### 新增請求欄位

| 端點 | 欄位 | 說明 |
|---|---|---|
| `POST /v1/session/consent` | `maxUses: number \| null` | 真正的「只這一次」。`maxUses: 1` 由**第一次成功授權的派工**用掉；並行的兩個 plan 只有一個通過；dispatch 失敗**不歸還**次數；重啟後仍是用掉的狀態。省略或 `null` ＝ 沿用歷史語意（TTL 內不限次）。`maxUses: 0` 直接拒絕。Consent 內部新增 `maxUses`／`remainingUses`（`serde(default)`，舊 session blob 原樣載入）。**目前只有動器派工路徑會消耗次數**——受器與 tool-operation 的授權仍是短效 TTL。 |

### 新增回應欄位

| 端點 | 欄位 | 說明 |
|---|---|---|
| `GET /v1/memory/export` | `total: number` | 資料庫真實筆數（`SELECT COUNT(*)`），不再從「這一頁 1000 筆剛好裝滿」推論。`limitReached` 現在是 `total > 1000`——**剛好 1 000 筆不再誤報截斷**。 |
| `GET /v1/memory/export` | `included: string[]` | 固定為 `["memory-items"]`。 |
| `GET /v1/memory/export` | `notIncluded: string[]` | 由粗略的 `["knowledge","assets","character-interaction-memory"]` **精確化**為 `["knowledge-nodes","assets-and-derivatives","knowledge-receipts","character-interaction-memory"]`（補上先前漏列的知識收據）。`note` 文案同步。**讀取端若對舊字串做比對需要更新。** |
| `GET /v1/providers/{id}` | `detail.tested.pairingUnverified: bool` | 裝置回報 `hello.pairing=false`（配對碼從未被比對）時為 `true`。`serde(default)`，為 `false` 時不寫入，**舊記錄不會長出這個欄位**。`tested_note` 同步改為「這次握手無法證明配對碼被比對過（裝置說它不需要配對），身分證據僅為裝置自報的 deviceId」。對抗審查 protocol-conformance-042 之後，**同一條連線上曾經比對過碼的通道**（hello.pairing=true→pair-ok）在裝置之後回報「已配對、不必重比」時不再標 `pairingUnverified`（收據改註 `pairingNotRecompared: true`，目前無下游消費者）；daemon 重啟後第一次握手仍是保守的 `pairingUnverified`。無法知道配對狀態的來源（人為測試、受器讀取）傳 `None`，**不會**把先前的未驗證標記洗成乾淨。 |
| `GET /v1/memory` | `total`／`limit`／`limitReached` | 與 `/v1/memory/export` 同一套誠實模式：`total` 是同一 layer 過濾條件下的 `COUNT(*)`，`limitReached = total > limit`。一般模式的記憶分類不再對超過 200 筆的資料說「這個分類目前沒有記憶」。 |
| `emergency-stop` 事件／audit／outbox | `totalActuators`／`unconfirmedActuators[]` | 每個沒有在 2 秒內確認停止的動器逐一列出（`outcome: failed`＋driver 錯誤，或 `unconfirmed`＋「no stop confirmation within 2 s」）。只有全部確認時人話才是「所有輸出已中止」。 |
| `POST /v1/character/instances/{id}/events` | `{decision:"audit-only", reason:"input-capability-not-declared"}` | 桌面角色送出 manifest（或協商結果）沒宣告的輸入種類時的回應（外部 adapter 維持 `external-adapter-input-not-observed`）；純 Gateway 層對應的 `InputDropReason` 是 `capability-not-declared{requires}`（golden schema 純加法）。呼叫端不得把它讀成「已變成觀察」。 |
| audit `emergency-stop`／`stop-all`／`action.cancel` | `actor` | 依 token 種類歸因：human→`api`、legacy agent→`agent`、session token→`agent:{agentId}@{sessionId}`、adapter→`adapter:{id}`（與 `sensors_stop` 一致）。讀 audit 的工具若假設固定是 `api` 需要更新。 |
| agent session 記錄（`GET /v1/agent-sessions`／`/{id}`） | `resolvedWorkdir: string` | `gateway_attach` 實際掛載的 canonicalize 後絕對路徑。`serde(default)`，純加法。桌面「接續上次」優先用它；由 `dataScope` 推導的 fallback 會被標為未確認。 |

### 行為變更（BREAKING）

| 端點 | 變更 |
|---|---|
| `POST /v1/session/consent` | **`receptor:`／`tool:` scope 帶 `maxUses` 一律 `400`**（訊息指明「nothing spends a use on this scope… use expiresMinutes instead」）。這兩類 scope 從來沒有任何路徑會消耗次數，v0.5.1 不再收下再靜默當 TTL 用。`actuator:`／`channel:` 不受影響。 |
| `GET /v1/agent-sessions/{id}/messages` | session token **只能讀自己 session** 的 mailbox（中介層放行 `id == capability.session_id`，handler 再比對一次）；human token 不變。先前 session token 一律 403，現在對自己的 session 可達，並以 `MailboxReader::Agent` 記錄 fetched／acknowledged。 |
| `POST /v1/agent-sessions`（續開） | 續開比對**實際生效的工具開關**：上次是零工具（`toolScope == ["conversation.generate"]`）、這次不是（含空集合）→ `PolicyBlocked`；帶 `resumeProviderSessionId` 但查無紀錄、或舊紀錄沒有 `resolvedWorkdir` → `PolicyBlocked`。呼叫端續開 intent-only session 時必須原樣帶回 `["conversation.generate"]`（桌面與 CLI 已改）。 |
| `PATCH /v1/proactive-dialogue` | `generativeAgent` 只接受 `claude-code` 或 `null`；`codex` 回 `Validation`（Codex 無法確定性停用工具）。既有設定存 `codex` 者不會被改寫，但主動式訊息會誠實回 `ConsentRequired`「尚未由使用者選擇主動式對話 Agent」。 |
| character manifest 匯入／驗證 | `fallbacks.intents` 出現**安全 intent → 非安全 intent**（例如 `request-consent: "greet"`、`emergency: "sleep"`）一律回錯誤（Rust `ManifestErrorCode::Fallbacks`／TS `c.err`）。第三方 manifest 若依賴這種映射需改走能力鏈或接受 `system.text`；舊 Character Pack 的自動遷移不再產生這類映射。 |
| `POST /v1/agent-sessions/{id}/interrupt` | **legacy 共享 agent token（`state/api-agent-token`）一律 `403 token_scope_forbidden`。** 它沒有 session 身分、也不能建立或列出 session，無法證明擁有權。改用該 session 的 `INTERACT_AI_SESSION_TOKEN`（只能中斷自己的 session），或交給人類平面（human token 保留對任何 session 的管理能力）。runtime 的緊急停止走內部呼叫，不受影響。防禦深度：middleware 既有比對之外，handler 再加一層 `interrupt_principal_allowed`。 |

### 執行期行為誠實化（非 BREAKING，但回應內容會不同）

- **provider 生命週期真的擋得住**：擁有某能力的 provider 處於 `Disabled`／`Expired`／`Revoked`／`Closed`
  時，`observe` 回 `Unavailable`，`execute` 與 `simulate` 回 `Blocked{rule:"provider.not-operational"}`，
  能力清單投影為 `Availability::Disabled`（**不新增 enum 值**）。共用能力（多台 iPhone、多個 agent
  session）只在**所有**擁有者都停下時才擋；`Installed`／`Paired`／`Disconnected` 是連線事實不是決定，
  不擋。內建與無擁有者的能力不受影響。
- **升級邊界**：舊版落地的 `Disabled`／`Revoked` provider 若沒有 `provider-off` 標記，**第一次重啟就採
  安全預設**（不重開連線、能力停用），同時補寫標記並留 `provider.legacy-off-assumed` audit 請使用者確認。
  runtime 自己發起的重啟降級被排除在外，重啟不會變成永久停用。
- **`cancel_action` 不再無條件寫 `Cancelled`**：只有 driver 在 2 秒內確認才是 `Cancelled`；回錯、逾時、
  動器不可達一律 `Uncertain`（附 `cancel_unconfirmed` 錯誤）。**內建動器（conversation／通知等）本來就
  收不回，取消一律誠實回 `Uncertain`。** 呼叫端若假設「取消一定成功」需要更新。
- **工作資料夾不得位於 runtime `state/` 底下**：`resolve_gateway_workdir` 的檢查改為雙向（原本只擋
  「等於或包含 state 目錄」，現在也擋「位於 state 目錄之下」）。runtime 自己的主動式對話工作區已從
  `state/proactive-agent-workspace` 搬到 `agent-workspaces/proactive`。

## 2. CLI

| 指令 | 變更 |
|---|---|
| `interact-ai session consent <scope> --max-uses <N>` | 新旗標。`--max-uses 1` ＝ 真正的「只這一次」；省略 ＝ 歷史的 TTL 內不限次。**只對 `actuator:`／`channel:` 有效**；`receptor:`／`tool:` 帶它會被拒絕（改用 `--expires-minutes`）。 |
| `interact-ai agents resume <id>` | 續開 intent-only（`toolScope == ["conversation.generate"]`）的工作階段時原樣帶回該值；其餘維持空集合。否則後端會以「宣告更窄、實權更寬」誠實拒絕。 |
| `interact-ai agents resume <id> --max-cost <USD>` | 新旗標。**省略時帶入原 session 的實際上限**，不是 runtime 預設（後者較寬會被拒絕）。 |
| `interact-ai agents resume <id> --max-messages <N>` | 新旗標，語意同上。 |
| `interact-ai agents resume <id> --workdir <PATH>` | 語意收緊：省略時採用記錄的 `resolvedWorkdir`；**續開不得移動到別的資料夾**。 |

**BREAKING（CLI 可見）**：升級前建立的 gateway session 記錄沒有 `resolvedWorkdir`，`agents resume`
一律 `PolicyBlocked`（「不確定就拒絕」）——需要重新建立 session 並明確指定資料夾。純對話 session 不受影響。

## 3. Tauri IPC（桌面程式內部契約）

| 指令 | 變更 |
|---|---|
| `companion_hit_regions`（新） | payload `{ regions: [{id,x,y,w,h}] }`——角色本體、每隻使魔、每個可抓玩具、每個真正互動的 UI 各一個矩形。游標只在落於某個 region 時才被攔截，其餘位置設 `ignore_cursor_events`。上限：region 數 ≤16、逐一 clamp 到視窗、單框不得兩軸皆 ≥80% 視窗、總面積 ≤80%；空清單／非有限值**整份拒絕並沿用上一份有效 regions**（fail-closed）。host 端每 45 ms 最多接受一次。`id` 只作診斷用，**不授予任何權限**。 |
| `companion_hit_rect` | **保留為單矩形相容 shim**（與新指令共用 `store_hit_regions`），舊呼叫端不會壞。 |
| `consent_grant` | 新增 `max_uses: Option<u32>` 參數，一路轉發到 runtime。桌面「只這一次」對動器送 `maxUses:1`（並保留 5 分鐘 TTL 當雙重保險）。**HTTP transport 也一併轉發**，避免桌面路徑靜默退化成純 TTL。 |

renderer 端新增純函式模組 `src/companion/hitRegions.ts`（幾何、去重、與 Rust 同一組上限、回報政策
≥50 ms／位移 >4 px／≤60 ms 心跳）；拖曳中角色 region 持續存在並外擴 8 px；整窗攔截只剩文字輸入與
拖放確認兩種情況。

## 4. iOS App

| 項目 | 變更 |
|---|---|
| 連線意圖旗標（`UserDefaults`） | 新增。記錄「使用者上次是否想要連線」。按過「立即中斷」、配對被撤銷（`auth-fail`）、配對失敗、解除配對之後**不會**自動連；從 v0.5.0 升級上來、沒有這筆紀錄但有配對資料時視為「想要連線」。 |
| 冷啟動自動重連 | 新增 `connectOnLaunchIfDesired()`：系統終止後冷啟動時，若 Keychain 有配對且上次意圖是想連線，自動走既有 1 s→15 s 退避重連，不再需要手動點「連線」或 DEBUG `--auto-connect`。**不變量未削弱：感測一律不自動恢復**（`SensorCenter`／`BleGateway` 每次啟動全關）。 |
| 位址變更提示 | 新增純函式 `ReconnectDiagnosis`：**連續 4 次**連線層失敗（timeout／找不到主機／主機不可達／連線被拒），或同一串失敗**持續 ≥60 秒**時，顯示固定文案「連不上桌面：可能是桌面的網路位址已變更。請在桌面重新產生配對碼並重新配對。」並提供「重新配對」捷徑。**TLS 指紋不符與撤銷維持各自文案**，且任何一筆這類失敗都會打斷連續串，不會被誤報成「位址變更」。 |

真機驗證 blocked（見 `docs/releases/v0.5.1-iphone-device-evidence.md`）——**不得寫成真機已驗收**。

wire protocol 本身無變更。

## 5. Breaking 變更彙總

1. **`POST /v1/agent-sessions/{id}/interrupt` 拒絕 legacy 共享 agent token**（`403 token_scope_forbidden`）。
   遷移：改用該 session 的 `INTERACT_AI_SESSION_TOKEN`，或交給人類平面。
2. **升級前建立的 gateway session 無法續開**（記錄缺 `resolvedWorkdir`）。遷移：重新建立 session 並
   明確指定工作資料夾。
3. **`cancel_action` 未經 driver 確認一律回 `Uncertain`**（不再無條件 `Cancelled`）。遷移：呼叫端不得
   把「送出取消」讀成「已取消」。
4. **內建動器的取消一律回 `Uncertain`**（conversation／通知等本來就收不回）。這是第 3 點的必然結果，
   單獨列出是因為它會改變日常最常見的取消路徑的回應。
5. **`receptor:`／`tool:` scope 的 `maxUses` 一律 `400`**（對抗審查 safety-invariants-058）。遷移：改用 `expiresMinutes`／`--expires-minutes`。
6. **character manifest 的安全 intent → 非安全 intent fallback 被拒**（character-protocol-036）。遷移：刪掉該映射，缺美術的安全
   intent 改走 `fallbacks.capabilities` 或接受 `system.text`。
7. **主動式對話 `generativeAgent` 不能是 `codex`**（agent-honesty-022）。遷移：改選 `claude-code` 或關閉。
8. **續開 intent-only session 必須原樣帶回 `toolScope`**（agent-honesty-023）；找不到紀錄或缺 `resolvedWorkdir` 一律拒絕（025）。
   桌面與內建 CLI 已改；自製呼叫端需要跟上。
9. **已關閉的 agent session 會被清理**（agent-honesty-024）：保留最近 200 筆／30 天，超過者從記憶體與 SQLite 刪除並留
   `agent-session.history-pruned` audit。長期保存請自行匯出。

## 6. Storage／Schema

- **無 schema 版本變更**（沿用 v0.5.0 的 storage 版本）。
- 本輪所有新欄位（`Consent.maxUses`／`remainingUses`、`ProviderTested.pairingUnverified`、
  `AgentSessionRecord.resolvedWorkdir`）皆為 `#[serde(default)]` 的加法欄位，舊資料原樣載入。
- 新增的 `Store::count_memory(layer)` 與 `Store::transaction` 是唯讀 COUNT 與既有連線上的交易封裝，
  不改表結構。
- `schemas/character-protocol.schema.json`（golden）：`InputDropReason` 新增 `capability-not-declared{requires}`，純加法。
- 已配對 iPhone 清單（`state/mobile-devices.json`）改為原子寫入（tmp 0600＋fsync＋rename）；載入錯誤不再吞掉。

## 7. 使用者可見文案變更

| 位置 | 變更 |
|---|---|
| 工作頁狀態標籤 | 對齊產品用語：**正在準備／已交給工作助手／處理中／等你回答／等你允許／對方說已完成／已由你確認／逾時失敗／失敗／已取消／結果不確定**。「對方說已完成」保留 warn 徽章、「對方的說法，尚未檢查」註記與待你裁決，**仍然沒有綠勾**。 |
| 工作送出結果 | 由固定的「已送達、尚未完成」改為六態投影（已送達／尚未送達（已放進信箱）／排隊中／Agent 不可用／傳送失敗／結果不確定），各附一句人話與誠實註記；**只有後端蓋了送達戳記才說「已送達」**；原始後端文字只在進階模式顯示。 |
| 「現在」頁空狀態 | 待決定精確為 0 時明確顯示「目前沒有需要處理的事」（後端只回下限時維持「至少 N 項」）。 |
| 備份與還原頁 | 「備份／這個備份」改為「**匯出的記憶檔**／這裡匯出的」，不再暗示是完整備份；範圍改為**轉述後端回報的** `included`／`notIncluded`（後端沒給就不顯示，不由前端補一份好看的清單冒充後端承諾）。 |
| 「只這一次」授權 | 動器：「用過一次即失效；5 分鐘內未使用也失效」。受器與 tool-operation：維持誠實的 TTL 文案（不宣稱只准用一次）。 |
| iPhone 卡片 | 新增「**重新配對**」（導到既有配對區）；未連線時提醒「若桌面的網路位址變了，需要重新配對」；進階模式的原始欄位改成「**連接診斷**」區塊（deviceId、pairedAt、連線狀態與感測旗標原始值），**一般模式完全不顯示**。 |
| 能力階梯（六階） | 裝置回報未比對配對碼時，「已測試」「已啟用」降為警告色的「（配對碼未驗證）」。 |
