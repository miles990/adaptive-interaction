## 3. v0.5.1 新增的窄限制（每一項都是某個修復刻意劃定的邊界）

1. **受器與 tool-operation 的 consent 仍是 TTL，不是單次**。`maxUses` 只在動器派工路徑被原子消耗；
   受器範圍（`receptor:*`）與 tool-operation 的授權沒有經過那個計次臨界區，桌面「只這一次」對這兩類
   仍維持誠實的 TTL 文案（不宣稱只准用一次）；對抗審查 safety-invariants-058 之後，這兩類 scope 帶 `maxUses` 會被
   **明確拒絕**（HTTP 400／CLI 錯誤），介面不再回報它不強制的 `maxUses`。要補齊需要在受器讀取路徑也加計次臨界區。
2. **首次設定 commit 在「檔案已寫、SQLite 未提交」之間崩潰沒有 journal**。Phase 2a 已把 SQLite 列
   收進單一交易並在交易失敗時回寫檔案舊 bytes，但**程序在兩者之間被砍**（斷電、SIGKILL）時沒有
   journal 可以重放，會留下 policy.yaml 已更新而 SQLite 未更新的狀態。這是本輪誠實承認的唯一
   不可化約缺口，錯誤訊息與 `onboarding.partial` audit 會說明，不是隱藏。
3. **受器讀取路徑拿不到 `pairingUnverified`**。旗標只從**動器 driver 收據**一路投影到 provider 證據；
   由人為測試或受器讀取產生的「已測試」記錄傳 `None`——它們不會把先前的未驗證標記洗成乾淨（安全方向
   正確），但也**不會**在只有受器讀取的裝置上主動標出「配對碼未驗證」。
4. **【已於 `feature/v0.6.x-maintainability` 修正】** `transition_provider` 到 Disabled／Revoked／Closed／Expired 時同步翻掉該 provider
   受器／動器的 enabled 旗標並寫 `provider.capabilities-disabled` 稽核；回到 Available **不**自動恢復任何能力（測試
   `transitioning_a_provider_to_disabled_turns_off_its_capability_flags`、`re_enabling_a_provider_never_re_arms_its_capabilities`）。
   原文：**`simulate_plan` 已擋，但 `transition_provider` 不會關掉 registry 旗標**。provider 轉成 Disabled／
   Revoked 後，`ProviderGate` 會在 observe／execute／simulate 三條路徑攔下來（能力清單投影為
   `Availability::Disabled`），但 `CapabilityRegistry` 裡該能力自己的 enabled 旗標**沒有被翻掉**——
   兩者不同步不會造成安全漏洞（gate 在更外層，一律拒絕），但讀 registry 原始旗標的程式碼會看到
   「enabled: true 但實際被 gate 擋住」的組合。
5. **Reduced Motion 未在真 Tauri 視窗驗收**。`defaults write com.apple.universalaccess reduceMotion`
   在本環境被系統拒絕，無法自動切換 OS 設定；需人類在系統設定切換「減少動態效果」後觀察角色重新
   協商。目前只有單元測試與 Playwright（瀏覽器模擬 media query）覆蓋。
6. **快捷選單／玩具／使魔與 adapter 崩潰 fallback 未在真 Tauri 視窗驗收**。CGEvent 點角色本體確認角色
   有反應（表情），但截圖區域內未捕捉到快捷選單；丟玩具／使魔互動、以及 adapter 崩潰後退回固定文案的
   fallback 都無法在真視窗誘發，只有 jsdom＋vitest（`companion-gateway-wiring`）覆蓋。
7. **iPhone 冷啟動自動重連與位址變更提示只有模擬器證據**。`ConnectionManager.connectOnLaunchIfDesired()`
   與 `ReconnectDiagnosis` 的驗證等級是 **iPhone 17 模擬器 XCTest**（`ReconnectHintTests` 21 條，純決策
   函式）。真機驗證因鑰匙圈授權對話框而 blocked，App 從未裝上手機、冷啟動測試 0 次執行。
   **不得寫成真機已驗收。**
8. **角色效能浸泡的 GC 後保留集合升到 +523 KB（觀察項，來源未定位）**。10 分鐘浸泡 after-GC
   Δ +523 KB（21.2%），60 秒兩次為 +510／+446 KB。10 分鐘不比 60 秒大，方向上像固定保留集合而非洩漏；
   但比 v0.5.0 同一量測（+223／+210 KB）高出一倍以上，**尚未做 heap snapshot 比對定位來源**。
   不宣稱無害，也不宣稱是洩漏。30 分鐘浸泡未執行。
9. **角色視窗被主視窗遮蔽時會週期性重新 hello（macOS 行為）**。真 Tauri 視窗觀察：角色視窗落在主視窗
   下方時 WebKit 暫停繪製，Runtime 每 ~21 秒收到重新 hello（generation +2）；移出遮蔽後恢復、
   generation 停止增加。角色視窗非置頂時被蓋住是正常 macOS 行為，**不是缺陷**，但會讓 instance
   generation 持續增加，讀取該數字的診斷需知道這件事。
10. **故障注入接縫編進正式碼**。`Store::force_next_transaction_error`、
