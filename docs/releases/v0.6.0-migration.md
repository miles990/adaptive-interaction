## 1. 新增 HTTP 路由（human token）

| 路由 | 用途 | 來源 |
|---|---|---|
| `GET /v1/character-session` | 權威 snapshot（`state{kind:"snapshot"}` envelope） | `crates/interaction-api/src/routes.rs::character_session_snapshot`(:1846) |
| `POST /v1/character-session/resume` | `{lastRevision,lastSequence,epoch}` → patches 或 snapshot | `routes.rs::character_session_resume`(:1876) |
| `POST /v1/character-session/events` | 可信 host surface（桌面）送語意事件 | `routes.rs::character_session_event`(:1902) |
| `GET /v1/character-session/diagnostics` | 不含 token／路徑／原始 payload 的計數與成員列表 | `routes.rs::character_session_diagnostics`(:1856) |

四條路由都受 `INTERACT_AI_CHARACTER_SESSION` feature flag 管制（§5）；`agent` token／agent session
capability token／character adapter token 一律拒絕（human-only，`docs/aip/transport-bindings.md` §2）。

## 2. 新增事件（SSE）

`character.session.state`（`GET /v1/events`，human token）：payload 是完整 AIP envelope
（`state{kind:"patch"｜"snapshot"}`），每次廣播都送一次；`capability`／`command`／`result` 送給桌面
可信 host surface 時也走這個事件型別。與既有 `character.*` 事件同界線：agent token／adapter token
一律看不到。詳見 `docs/aip/transport-bindings.md` §3。

## 3. 新增 CLI

```bash
interact-ai character session status                       # GET /v1/character-session
interact-ai character session diagnostics                  # GET …/diagnostics
interact-ai character session resume --last-revision N [--last-sequence M] [--epoch E]
```

來源：`crates/interaction-cli/src/main.rs::CharacterSessionAction`（:738-755）。這是薄殼（human
token），**不能**送語意事件——`character.interaction.*` 必須來自綁定身分的 surface（手機或桌面
視窗），安全 intent 只能由 Runtime 真相投影產生（`docs/aip/transport-bindings.md` §4）。

## 4. 新增 fake_iphone fixture op

**模擬 iPhone（fixture）**，不是真機驗收。`cargo run -p interaction-runtime --example fake_iphone`

## 5. Feature flag：`INTERACT_AI_CHARACTER_SESSION`

環境變數，預設 `1`。`0` 時：

- Runtime 不啟動 Session Host（`character_session_enabled_from_env()`，
  `crates/interaction-runtime/src/character_session.rs:62`）。
- §1 四條路由全部回 `503 session-disabled`（`require_character_session`，`routes.rs:1832`）。
- iPhone 的 `aip` frame 回 `error{unsupported-capability}`。
- 其餘行為與 v0.5.1 相同（回退路徑）。

## 6. Rust API 變更

| 變更 | 狀態 | 說明 |
|---|---|---|
| `migrate_legacy_pack` | **deprecated（非 breaking）** | `crates/interaction-character/src/manifest.rs:1719`，`#[deprecated(since="0.6.0", note="use migrate_pack_to_manifest with a host MigrationRegistry; this path only migrates sprite packs")]`；內部改呼叫 `migrate_pack_to_manifest(json, &MigrationRegistry::with_core_migrators())`，行為不變（只剩 sprite），舊呼叫端仍可編譯，只會看到 deprecation 警告 |
| `ValidationLimits::default().builtin_whitelist` | **改為注入（非 breaking，但呼叫端需自行注入白名單）** | 核心不再內建任何具名 adapter；`interaction_runtime::character::character_host_registry()` 提供 Runtime／Tauri 共用的白名單（`shu-rig`／`shape`／`sprite`／`text`）。第三方直接依賴 `interaction-character` 且沒有自行注入白名單的呼叫端，會發現所有 builtin entrypoint 都被拒絕——這是刻意的行為改變，但屬於「核心變得更嚴格中立」而非「破壞既有 wire 協定」 |
| `BUILTIN_ENTRYPOINTS` 常數 | **已移除** | 本次以 `grep -rn "BUILTIN_ENTRYPOINTS\b" crates/interaction-character/src` 核實零命中；`rg -c -i "shu|maid" crates/interaction-character/src` 同樣零命中，符合 strangler 目標（`docs/aip/architecture-boundaries.md` §4） |
| 新 crate `interaction-character-shu` | **新增** | `ShuRigPack`：`ENTRYPOINT_ID`、`VARIANTS`、`capabilities()`、`input_capabilities()`、`migrate()`、`migrator()`；小樞專屬內容從核心搬出 |
| `MigrationRegistry` / `PackMigrator` trait | **新增（核心）** | `crates/interaction-character/src/manifest.rs`：`PackMigrator`(:1580)、`MigrationRegistry`(:1609)、`register()`(:1638)；核心內建只有通用 sprite |

## 8. Breaking 變更：目前沒有對舊 iPhone App 的 breaking

**舊 iPhone App（不送 `capability` 的版本）完全不受影響**：iPhone 線協定 v1 的既有訊息全部保留，
`aip` frame 是全新增訊息型別，`character.present` 動器與 `iphone.touch` observation 路徑不變。
沒送過 `capability` 的舊 App **永遠不會**收到任何 `aip` frame——回歸測試：
`crates/interaction-runtime/tests/mobile_loop.rs::a_legacy_phone_that_never_negotiates_receives_no_aip_frames`
(:3759)。這是本文件對「沒有 breaking」這句話唯一的測試支持；本次任務未重新執行這個測試，
只核實其函式定義存在於 HEAD。

其餘已知的行為變更都在 §6／§7 標為「deprecated」或「需自行注入」，沒有任何一項會讓舊呼叫端
編譯失敗或既有 wire 訊息被拒絕。
